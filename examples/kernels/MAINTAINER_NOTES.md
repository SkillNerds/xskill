# 算法内核文档维护笔记

这份笔记记录算法内核开发指南的长期验收约束。后续修改
[README](README.md)、实现示例、评测命令或项目级 Agent Skill 前，先阅读并逐项核对。

## README 定位

- 面向第一次接触 XSkill 的算法工程师，写成可直接执行的用户手册，不写成任务汇报。
- 正文主线固定为：接入算法内核、数据集评测与迭代、上线后的评测与迭代、Agent 辅助开发。
- 公共对象字段、发布细节和架构边界放在附录，不让平台内部实现污染新人认知。
- 标题使用陈述句，不用自问自答或争论式标题。
- 不介绍历史协议、内部版本沿革和未交付的未来设计。

## 事实与命名

- 只写已经实现、实际跑通并有测试保护的能力。
- 用户命令、参数名、默认值、路径解析、输出字段和窗口上限必须与代码逐项一致。
- 示例目录使用 `your-demo-algo-kernel` 这类用途明确的名字，不使用容易被误解为产品模块的
  `starter`，也不使用无意义的公司占位名。
- 面向开发者使用“算法内核实现脚本”和 `KernelMetadata`，避免 `bridge`、`manifest` 等
  非必要黑话。
- 明确区分可运行示例、真实 SDK 适配和仅展示形状的不可运行示例。

## 评测口径

- `xskill eval` 不只报告运行成功，还要展示数据集上的有效评价指标、通过数和总样本数。
- 可以调研其他评测系统来理解指标、分片与展示方式，但 XSkill 的公开实现和文档不能透露其
  私有信息、绑定其数据或依赖其服务。调研结论只能沉淀为提供方无关的抽象。
- 评价数据、评价脚本、模型、私有配置和评分协议由算法提供方维护；XSkill 只运行明确选择的
  可信评价器、校验标准结果、保存证据并展示指标。
- 终端输出提供紧凑的 metric table，例如 `spreadsheet  85.71%  60/70`。
- 算法自报指标、外部独立 benchmark 和线上用户 UX 必须分开标注来源。
- 抽样、数据集身份、测试窗口和最多记录数等限制必须在结果与文档中显式呈现。

## Agent Skill 位置

- 算法内核专用 Skill 是本目录的项目级资源：`.agents/skills/xskill-kernel/`。
- README 直接告诉开发者在本项目中使用该 Skill，不通过 `xskill init` 安装。
- Skill 内保存面向 Agent 的完整 API、诊断和评测操作；README 只保留人类最短路径。

## 每轮交付检查

1. 清除所有双 at 批注和临时讨论文字。
2. 实际执行 README 的最短命令，并检查产物与示例输出。
3. 核对 README、架构说明、项目级 Skill 和 CLI 帮助中的术语与参数。
4. 运行相关测试、格式检查、Markdown 链接检查和 `git diff --check`。
5. 交付前让独立子代理按本笔记复核；发现文档承诺超过实现时，先修实现或收窄文案。
