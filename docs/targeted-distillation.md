# 指定技能蒸馏

本地 native 管线支持将一次蒸馏运行限制到一个技能。默认仍为 `auto`，原有自动生成与更新方式保持不变。

| 模式 | 输入 | 约束 |
| --- | --- | --- |
| `auto` | 现有配置 | 自动决定创建和更新哪些技能 |
| `create_one` | 技能名称、说明 | 只创建指定技能；同名目录已存在时失败 |
| `update_only` | 已有技能名称 | 只更新指定技能；目标缺失或包含来源不明的未提交内容时失败 |

技能说明使用现有 `description`。新建由用户提供；更新读取已有说明和正文。系统继续使用原有写作规则、素材分数门槛、提交与灰度流程。

## 使用

先正常停止本地 `serve`，等待它的宿主和 worker 退出。前台服务使用 Ctrl+C；其他托管方式停止对应宿主。`xskill stop` 用于团队 connect 任务，不能代替本地 `serve` 的停止。

```powershell
xskill distill configure --mode create_one --skill feishu-bug-troubleshooting --description "用于排查和解决飞书接口及集成问题"
xskill serve
```

`configure` 只准备运行，不调用模型，也不开始读取历史；技能草稿在 worker 获得运行锁并完成校验后建立。

查询当前模式、运行记录和处理数量：

```powershell
xskill distill status --json
```

停止服务后，改为更新已有技能：

```powershell
xskill distill configure --mode update_only --skill feishu-bug-troubleshooting
xskill serve
```

新建名称使用小写连字符形式。更新使用现有技能的准确目录名，程序不会自动替换成相近名称。

## 素材处理

相关素材加入目标候选池；无关素材记录原因并跳过。素材达到现有门槛后才整理技能，不会为了产出而抬高分数。

同一运行按来源、Atom 和内容指纹记录进度。过去已用于其他技能的历史仍可以参与定向判断；定向处理不会清除或重置默认模式的全局学习标记。历史原文保持不变。

不同来源出现相同 Atom ID 时，现有候选格式无法区分证据，系统会记录冲突并拒绝混入，避免覆盖不明来源的素材。更新目标原有的候选仍可被处理；本功能不提供“只使用选中轨迹”。

## 权限与后台任务

固定目标限制覆盖正文、脚本、参考材料、元信息、候选池、Git 提交和框架后台写入。读取其他技能不会改变写入权限。受限模式禁止重命名和跨技能移动素材。

其他技能的候选、脚本化、灰度和编辑回流暂不执行，积压保持待处理。旧 Generate 任务也不会被认领。管理性导入、删除、回滚和重建等写操作在受限运行生效时拒绝执行。

同一个真实技能库不能同时运行两个 native 蒸馏 worker。路径穿越、符号链接、junction、硬链接别名和 Git 仓库外部引用会被拒绝。该机制约束 XSkill 管理的入口，不是任意 Python 扩展的操作系统沙箱。

## 中断、恢复与切回自动

未关闭的受限记录会在重启 `serve` 时继续加载。恢复仍使用原模式、目标和权限；异常不会自动切回 `auto`。

也可以停止服务后明确恢复原运行：

```powershell
xskill distill configure --resume <run-id>
xskill serve
```

创建归属不明、目标目录被替换、更新目标存在无法证明来源的未提交内容时，恢复会停止并保留现场。成功提交的 checkpoint 可以核对恢复；程序不会自动接管目录或覆盖人工内容。

checkpoint 按运行、来源、Atom 编号和内容指纹确认，编辑期间使用固定的证据快照。同编号的新内容不会被旧提交标成已经学习；提交说明中的模型文本不能提供处理凭据。已提交但尚未清理的候选可在恢复时继续清理，有新版本待处理时保留该候选。

早期仅记录 Atom 编号的 checkpoint 无法证明来源和内容版本。遇到这类提交及尚未确认的素材时，恢复会明确报错并保留现场；即使候选只存在文件中、还没有数据库记录，也不会猜测完成状态或自动重复消费。

checkpoint 核对最多读取 200 个可达提交。超出预算且仍有无法证明状态的素材时，恢复会停止并报告原因，避免重复学习已经消费的素材。

切回自动模式：

```powershell
xskill distill configure --mode auto
xskill serve
```

切换只结束旧运行的后续调度，保留其审计和产物。其他技能积压恢复正常处理。配置期间发现宿主或写 worker 未退出会报错；`--force` 不绕过运行锁。

## 理解结果

| 状态 | 含义 |
| --- | --- |
| `no_relevant_material` | 当前已检查素材没有适用项 |
| `waiting_evidence` | 候选尚未达到原有生成门槛 |
| `waiting_main_feedback` | 已有主版本缺少流程要求的使用评分 |
| `waiting_canary` | 等待已有灰度完成 |
| `draft` | 正文或 checkpoint 尚未形成完整产物 |
| `candidate_committed` | 有效灰度候选已提交，尚未晋升主版本 |
| `main_committed` | 有效主版本已提交 |
| `failed` | 权限、内容、提交或恢复失败，附错误原因 |

运行生命周期和产物状态分别记录。提交一个有效版本后，服务仍然运行，继续观察新素材；停止由用户控制。

成品检查包括固定名称、合法正文、非占位稿、本地引用文件和实际提交树。只有工作区完整、文件尚未提交，不能算已交付。文件存在检查不等于脚本功能已经验证；系统不会执行模型生成的任意脚本。

新建技能完成候选 checkpoint 后，如果最终正文或引用文件仍不完整，后续编辑会继续修复现有草稿，校验通过才晋升主版本；不会把已有 checkpoint 当作完整成品。灰度物化同时保留实际提交中的文件内容和脚本执行权限。

## 支持范围与评测

该入口用于单人本地 native 管线。团队模式和外部算法内核拒绝受限运行；它们在 `auto` 下保持原用法。界面表单、指定输入轨迹和自动停止不属于本功能。

默认自动模式做独立回归；指定模式用独立技能库和未参与蒸馏的任务评估。测试夹具验证隔离和流程，不代表真实模型效果，也不代表复现 README 的历史成绩。

完整设计见 [指定技能蒸馏限制最终设计与开发方案](superpowers/plans/2026-11-05-targeted-distillation-design-plan.md)。
